## 확인된 구조

### 문자 선택 그리드 — `0x08AEE0` 부근

이름 입력 화면에서 쓰는 문자표로 보입니다. **셀당 2바이트 고정폭**입니다.

- 반각 문자: `20 XX` — 상위 바이트가 `0x20`, 하위 바이트가 ASCII
- 전각 문자: Shift-JIS 2바이트를 그대로 저장
- 빈칸: `20 20`

구간별 내용:

| 오프셋 | 내용 |
| --- | --- |
| `0x08AEEC` | 전각 숫자 `０`–`９` |
| `0x08AF0C` | 전각 영대문자 `Ａ`–`Ｚ` |
| `0x08B020` | 전각 기호 (`．，・：；？！々ー／～（）「」＋－×÷＝＜＞％＃＆＊＠★●■▲〒♪`) |

시사점: 게임이 **Shift-JIS를 그대로 다루는 경로가 존재**합니다. 본편 스크립트가
같은 인코딩을 쓰는지는 아직 미확인.

## 미확인 / 진행 중

### 본편 스크립트 위치

평문 Shift-JIS 스캔 결과 ROM의 **0.82%(약 138KB)**만 SJIS로 읽히고,
그중 가장 긴 구간(`0x6E6C81`, 2,958바이트)조차 실제로는 `C9 99` 반복의
그래픽/사운드 데이터 오탐이었습니다.

> **가설**: 본편 스크립트는 압축되어 있거나 커스텀 인코딩을 씁니다.
> `make scan-lz` 로 GBA 표준 LZ77/RLE 블록을 전수 검증 중입니다.

### 엔트로피 분포 (1MB 단위)

대부분 구간이 6.2–6.9로 높아 압축·그래픽 데이터가 지배적입니다.

| 구간 | 엔트로피 | 0xFF 비율 |
| --- | --- | --- |
| `0x0000000` | 6.36 | 1.7% |
| `0x0900000` | 4.96 | 1.3% |
| `0x0B00000` | 4.96 | 1.1% |
| `0x0F00000` | **4.39** | **51.3%** |

마지막 1MB 구간이 절반 이상 `0xFF` — **번역문 삽입 공간의 1순위 후보**입니다.
(`tools/inserttext.py` 가 자동으로 잡아냅니다.)

### 포인터 테이블 후보

`make scan-ptr` 결과 26건. `build/scan_ptr.tsv` 참고.
`0x0B154C`(706개)가 가장 큼 — 대형 데이터 테이블일 가능성.
